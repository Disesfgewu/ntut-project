## ⚙ Lab 10 實驗設計與流程：結構保留式剪枝與微調實作

### 一、實驗設計  

本次實驗以保留通道剪枝後的 ResNet 架構為核心目標，採用 PyTorch 原生剪枝與模型再建構流程，以確保微調階段不會重新還原剪枝結構。並驗證不同剪枝比例下的參數變化與模型大小。

---

### 二、實驗流程  

#### Step 1. **L1 norm 剪枝通道選取**  
- 對每層卷積層所有通道計算 L1 norm：  
  \[
  L1\_norm = \sum |weights|
  \]
- 依比例（30%、50%、80%）選擇最小 L1 norm 通道進行移除。

#### Step 2. **結構剪枝並儲存壓縮模型**  
- 使用自訂 `prune_channels_from_layer()` 方法，結合 `torch.fx` / 模型重建邏輯，裁切架構。  
- 儲存包含完整結構的 `.pth` 模型（非僅 `state_dict`）。

#### Step 3. **微調階段修正初始化機制**  
- 進入 `build_os2d_from_config()` 階段時，將剪枝後模型作為 backbone 直接嵌入 `net.net_feature_maps`。  
- 避免從原始架構重新建構完整 ResNet50。

#### Step 4. **評估與記錄變化**  
- 比較不同剪枝比例下之：  
  - 模型大小（MB）  
  - 參數數量  
  - mAP 表現（@0.5）

---

### 三、實作程式碼範例（Prune + Save）  

```python
import torch
import pandas as pd
import os
import copy
from os2d.modeling.model_os2d import build_os2d_from_config
from config.config import cfg  # 輸入自定義 config

# 匯入通道清單
df_final = pd.read_csv("final_prune_list.csv")
example_input = torch.randn(1, 3, 224, 224).to("cuda")

# 載入原始 OS2D 模型
cfg.init.model = "./resnet_before_prune.pth"
net, _, _, _, _ = build_os2d_from_config(cfg)
backbone = net.net_feature_maps

# 執行剪枝（需定義好 prune_channels_from_layer 方法）
prune_channels_from_layer(backbone, df_final, example_input)

# 壓縮後模型建立與儲存
compressed_model = copy.deepcopy(backbone).cpu()
torch.save({"net": compressed_model}, "resnet_after_real_prune_0_8_full.pth")
```

## 🧪 Lab 10 實驗結報：剪枝結構保留與微調流程修正

---

### 一、實驗背景

在 Lab 9 已成功完成 L1 norm 通道剪枝與 `.pth` 模型儲存。預期將此剪枝模型作為 fine-tune 起點，可延續剪枝後的精簡結構進行訓練。但實驗中發現微調輸出 `.pth` 模型大小膨脹至 **77MB**，與原始 ResNet50 相同，推測 OS2D 框架於初始化階段重建了完整模型結構，導致剪枝結果無效化。

---

### 二、實驗目的

1. 保留剪枝後的結構與參數，並正確載入至微調訓練流程  
2. 解決微調後模型仍還原為完整架構之問題  
3. 確保剪枝比例影響可在模型大小與精度中呈現  
4. 評估剪枝 ➜ 儲存 ➜ 微調 ➜ 輸出之完整鏈是否成立

---

### 三、實驗流程摘要

#### 1️⃣ 剪枝與儲存

| 步驟 | 描述 |
|------|------|
| 使用 `prune_channels_from_layer()` | 根據每層通道的 L1 norm，移除貢獻最低通道（30%、50%、80%） |
| 儲存模型 | 使用 `torch.save({"net": pruned_backbone})` 儲存整體結構，檔案如 `resnet_after_real_prune_0_3.pth`（約 31.5MB） |

#### 2️⃣ fine-tune 設定與程式碼結構

目前的 fine-tune 程式碼主體為 `fine_tune_custom.py`，其邏輯如下：

```python
cfg.init.model = "./resnet_after_real_prune_0_3_full.pth"
net, box_coder, objective, img_normalization, _ = build_os2d_from_config(cfg)
trainval_loop(cfg, net, box_coder, objective, img_normalization, ...)
```

> ✅ 使用剪枝模型作為初始化  
> ❌ 但 `build_os2d_from_config()` 僅載入 `state_dict`，導致實際重建完整 ResNet50 結構

---

### 四、問題追蹤與處理紀錄

| 編號 | 問題描述 | 狀態 | 原因與分析 | 處理方式 |
|------|----------|------|-------------|------------|
| #1 | fine-tune 輸出 `.pth` 檔為 77MB | ❌ 尚未解決 | 結構自動還原為 ResNet50 | 需改寫初始化流程以讀入剪枝後 `net` |
| #2 | 儲存模型含多餘資訊 | ✅ 已解決 | 儲存含 optimizer / AMP 等暫存項 | 使用 `torch.save(state_dict)` 或保留 `net` 結構儲存 |
| #3 | 使用剪枝模型訓練但結構無效 | ❌ 尚未解決 | `state_dict` 被載入至預設 ResNet50 架構 | 需改寫 `build_os2d_from_config()` 增加 `cfg.model.pruned_backbone_path` |
| #4 | 模型無法驗證是否為剪枝後結構 | ✅ 已驗證方法 | shape 檢查與層數不符 | 使用 `named_parameters()` 或 `torchsummary` 檢查通道數是否精簡 |

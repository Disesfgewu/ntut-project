## 🔬 第六週實驗設計：L1 norm 設定通道剪枝依據

### 一、實驗目的  
本週目標為應用 L1 norm 作為通道重要性評估指標，建立初步的通道剪枝策略，並驗證剪枝比例與模型效能間的關係。

### 二、文獻依據  
參考 H. Li et al., *Pruning Filters for Efficient ConvNets*（ICLR 2017），提出以每個通道的 L1 norm 作為篩選依據，低 L1 norm 通道視為冗餘、可剪除。

### 三、實驗步驟  

1. **通道重要性計算**  
   - 針對每一層卷積層之每個通道（filter），計算其 L1 norm：
     \[
     L1\_norm(filter) = \sum |w_i|
     \]
   - 將同層通道依 L1 norm 由小到大排序。

2. **通道篩選與比對**  
   - 結合第 4～5 週所蒐集之通道活化資料與異常通道紀錄，驗證是否與 L1 norm 低值通道對應。
   - 區分：
     - 冗餘通道候選（低活化 & 低 L1 norm）
     - 關鍵通道（高活化或高 L1 norm）

3. **剪枝策略設計**  
   - **一次性剪枝（One-shot Pruning）**：  
     - 對模型進行一次性剪枝，分別剪除最低 L1 norm 通道的前 10%、20%、30%。
   - **逐次剪枝（Iterative Pruning）**：  
     - 每輪剪除 5% 最低 L1 norm 通道，逐輪觀察模型精度與推論時間變化，直到達 30%。

4. **模型訓練與微調**  
   - 剪枝後的模型進行微調（Fine-tuning）5~10 個 epoch，以穩定剪枝後性能。

5. **評估與記錄**  
   - 針對不同剪枝比例與策略，記錄以下指標：
     - Top-1 Accuracy（準確率）
     - 模型參數數量
     - 推論時間（ms/frame）
     - 模型大小（MB）

### 四、預期成果  
- 建立以 L1 norm 為基礎的剪枝框架  
- 評估不同剪枝比例下的效能變化  
- 初步定義通道篩選的有效依據

> - 這使剪枝失效，導致評估無法反映實際通道精簡效果。

### 三、問題分析與補充說明

本週實驗雖完成剪枝與儲存流程，但在微調後發現模型大小暴增（77MB），推測原因如下：

#### 🧨 問題推測：

1. OS2D 框架於 `build_os2d_from_config()` 階段會根據 YAML 自動重新構建完整 ResNet50 架構。  
2. 雖然載入了剪枝後的權重 `.pth`，但實際架構仍為原始 ResNet50，未反映剪枝後結構。  
3. 微調過程中，PyTorch 儲存時自動將所有模組展開與額外權重（如分類層或未使用通道）一併儲存，導致 `.pth` 體積暴增。

#### 🔧 當前儲存方式問題：

- 目前使用 `torch.save(model.state_dict())` 或 `torch.save({"net": model})`，但未正確處理初始化與剪枝結構綁定關係，導致訓練過程恢復為原架構。

### 四、後續改進方向

為解決上述問題與建立可持續剪枝的微調流程，規劃如下：

#### ✅ 解決方案：

1. **儲存方式調整**  
   - ✅ 改用 `torch.save(model)` 而非 `state_dict`，完整保留剪枝結構與權重。
2. **初始化流程修改**  
   - ✅ 改寫 `build_os2d_from_config()`，加入 `cfg.model.pruned_backbone_path` 判斷，若指定則直接載入剪枝後骨幹。
3. **結構凍結微調策略**  
   - ✅ 若無法維持結構，則嘗試凍結剪枝後的 backbone，僅微調 classification branch，避免權重重建。
4. **視覺化與對照紀錄**
